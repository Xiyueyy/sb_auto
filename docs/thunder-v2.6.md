# 雷霆战机 Auto 2.6.0：实时仿真

[一键安装](https://raw.githubusercontent.com/Xiyueyy/sb_auto/main/sb_thunder_auto.user.js)。选择 **后台稳定 → 实时仿真**，保分分数设为 **0** 可完整追分。

## 和 2.4/2.5 的区别

2.4/2.5 每局开打前要先把整局模拟完并验分，准备约 70～107 秒，期间不提交任何操作，之后再快速补交积压的输入。2.6 去掉了预演：

- **开局即打**：倒计时结束后第 1 秒就开始提交，之后严格每秒一块（60 帧），和网页自己的节奏一样。
- **触控仿真在规划里**：每次决策时，候选路线都带着触控抖动、反应延迟、不规则采样一起推演，选中的就是实际提交的输入。
- **回溯修补**：生成比提交超前约 30 秒。这段还没交出去，发现放跑敌机、补给机或漏接道具时，就从 1.6～3.2 秒前的存档换参数或换一条触控随机序列重走。事发 1.6 秒后的局面里失误更少，并且分数、生命、火力、连击都不低于原路线，才替换。已提交的帧永远不改。
- **修补分段执行**：每次心跳最多算 250 毫秒，先交到期的一块再往前算，提交节奏不受修补影响。缓冲少于 3 秒时不修补，先保证节奏。
- **结算核对**：服务器结算分数和本地引擎算出的不一致时停止，不再自动开局（说明引擎或协议变了）。

去掉了“仿真路线整局分数不低于原版”的验分，因为那需要先打完整局。

## 实测（引擎版本 1，离线）

### 实时运行

把真实脚本（含面板逻辑）放进 Node，接一个模拟服务器：真实时钟，每秒最多收一块，结算时用另一份全新引擎重放收到的输入计分。4 局并行。20 颗调参没用过的新种子：

| | 原版前瞻 | 2.6 实时仿真 |
| --- | ---: | ---: |
| 平均分 | 16031 | **16200** |
| ≥16000（最高奖励档） | 14/20 | **19/20** |
| 坠机 / 击败 Boss | 0 / 20 | 0 / 20 |
| 第一块提交 | — | 开局后 1～1.7 秒 |
| 相邻两块间隔 | — | 0.6～1.4 秒 |
| 比服务器允许进度最多晚 | — | 0.53 秒 |

只开触控仿真、不修补时平均只有 15824 分（9/20 过 16000），所以修补是把触控仿真的损失补回来、并且超过原版的关键。

### 不限时（生成器上限）

`batch-test.cjs` 在仓库原有的 8 颗种子上不限时运行生成器，平均 15629 → **16200**，8/8 击败 Boss、0 坠机，全新实例回放一致。种子 `1` 原版时间到也没打掉 Boss（12570），2.6 击败 Boss 得 16305。有 3 颗下降：14990132883620190655 降 250、4544080754576429201 降 245、18446744073709551615 降 10。

## 复验

```sh
node thunder-script/test.cjs

```

## 使用边界

结果来自离线引擎和模拟服务器，没有向网站提交过新对局；在线结算和反作弊判定都没有验证。慢设备上修补次数会变少，分数可能接近“只开触控仿真”的水平。
