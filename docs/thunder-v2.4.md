# 雷霆战机 Auto 2.4.1

基于 [Xiyueyy/sb_auto 原脚本](https://github.com/Xiyueyy/sb_auto/blob/main/sb_thunder_auto.user.js) 修改。验收标准：**同一种子的最终分数不低于原版，同时使用有实际位移变化的仿真输入**。

[一键安装 2.4.1](https://raw.githubusercontent.com/Xiyueyy/sb_auto/main/sb_thunder_auto.user.js)，替换原油猴脚本，刷新页面，选择 **后台稳定 → 保分仿真**。保分分数设为 **0** 可完整追分。前台可视使用原版方向键，保分仿真只在后台模式生效；选择“原版操控”可恢复原后台行为。

2.4.1 仅修改面板布局和版本标记，修复短窗口或页面缩放后顶部按钮超出屏幕的问题。面板高度随窗口调整，内容区独立滚动，顶部收起/展开按钮保持可见。已在真实浏览器的 6 种窗口尺寸下验证按钮点击、下拉选择、收起/展开和开始/停止，并通过现有单元及集成检查。下方 8 颗种子的对照结果来自 2.4.0；2.4.1 的游戏控制代码与该版本相同，源文件校验值单独记在 `validation.json` 的 `uiRelease` 字段。

## 保分与仿真

每局先用本局种子完整生成原版高分路线，再模拟触控目标追踪：有相关性的随机小幅偏移、1～3 帧不规则采样、变速和方向修正。敏感种子会尝试保留前段路线、后段仿真的方案。控制器使用独立且可复验的伪随机状态，不消耗游戏引擎的随机序列。

每个候选都实际跑到结局，只有最终分数不低于基线、剩余生命不减少、原版击败 Boss 时候选也击败 Boss，并且确实改变输入和飞机位置，才能选中。优先选择编码字节在 7000～10000 的合格路线；若其他种子只找到区间外的保分仿真路线，则保分优先。若没有合格仿真路线则停止，不退回未验分的路线。

选中的路线重新起局回放，提交时逐帧使用这份输入；最后一块提交前再次核对终局。运行失败、回放不一致或服务器结算低于基线时停止自动运行。接管已有对局时保留服务器收到的输入前缀，基线按相同前缀继续生成原版路线。

RLE 编码器与原版完全相同，仍合并相同输入。增加的字节来自实际操作变化。面板累计服务器已确认的 RLE 数据字节，重试不重复计数。字节数不包括 Base64、HTTP 和表单开销。

这是操作轨迹仿真，尚未用真人样本校准，不能据此认定反作弊会将其识别为真人。

## 使用边界

保分验收针对同一确定性引擎及完整传输的输入。此次验证均为引擎版本 1 的离线测试，没有向网站提交新对局；未验证在线结算或反作弊判定。

完整前瞻和候选验分发生在发送输入前，因此开局后有一段准备时间，面板显示进度。慢设备可能赶不上服务器时限；在捕获到的协议中，对局截止时间为开局后 160 秒。准备接近截止时间会停止并报错。准备结束后按服务器允许的进度补交输入，网络及服务端限制仍会影响在线结果。

原脚本保存在 `thunder-script/sb_thunder_auto.original.user.js`。随附的 HAR 派生文件只保留游戏输入和种子，不包含 Cookie、CSRF 或登录信息。

## 复验

当前工作区有 Node.js，无需安装依赖：

```powershell
node thunder-script/test.cjs
node thunder-script/batch-test.cjs
node thunder-script/verify.cjs sb_thunder_auto.user.js certified 14990132883620190655 7200 runtime
node thunder-script/verify.cjs sb_thunder_auto.user.js certified-prefix 14990132883620190655 7200 seed01 240
node thunder-script/verify.cjs sb_thunder_auto.user.js replay
```

批量测试默认复用已保存的原版基线，并重新验分及全新实例回放所有仿真路线。需要重新生成全部原版基线时运行 `node thunder-script/batch-test.cjs --fresh-baselines`。

`test.cjs` 检查设置、编码、确认重试、旧局回复隔离、控制器状态、最终分数门槛、已验分输入逐帧消费、开火位保留、回放不一致、结算不一致、重置、路线耗尽及未验分输入禁止提交。`verify.cjs` 与 `batch-test.cjs` 使用真实 WASM 检查完整对局。
